# Rails Preview Demo

A minimal Rails application for verifying preview deployments on [Railway](https://railway.app) and [Fly.io](https://fly.io).

## Tech Stack

| Layer | Technology | Version |
|-------|-----------|---------|
| Language | Ruby | 3.4.8 |
| Framework | Rails | 8.1.2 |
| Database | PostgreSQL | 17 |
| Web Server | Puma | 7.2.0 |
| Assets | Propshaft + Importmap | 1.3.1 / 2.2.3 |

## Features

- **Post CRUD** — scaffold with title (string), body (text), and published (boolean)
- **Health Check** — `GET /up` returns 200 if the app boots successfully
- **Dockerfile** — multi-stage production build generated by Rails 8.1

## Routes

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Root (redirects to posts#index) |
| GET | `/up` | Health check |
| GET | `/posts` | List all posts |
| GET | `/posts/new` | New post form |
| GET | `/posts/:id` | Show a post |
| GET | `/posts/:id/edit` | Edit post form |
| POST | `/posts` | Create a post |
| PATCH/PUT | `/posts/:id` | Update a post |
| DELETE | `/posts/:id` | Delete a post |

## Local Development

### Prerequisites

- Ruby 3.4.8 (managed via [asdf](https://asdf-vm.com/))
- PostgreSQL 17
- Bundler

### Setup

```bash
bundle install
bin/rails db:create db:migrate
bin/rails server
```

Open http://localhost:3000

## Deployment

### Railway

Deployment is configured via [`railway.json`](railway.json).

#### Configuration

| Setting | Value | Description |
|---------|-------|-------------|
| Builder | Dockerfile | Uses the multi-stage Dockerfile generated by Rails |
| Health check | `GET /up` | Rails built-in health endpoint (timeout: 300s) |
| Restart policy | On failure (max 5 retries) | Prevents infinite crash loops |

The Dockerfile's entrypoint automatically runs `db:prepare` before starting the server. No custom start command is needed.

#### Dashboard Setup

1. Create a new project and connect this repository
2. Add a **PostgreSQL** service
3. On the app service, add a variable: `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
4. On the app service, add a variable: `RAILS_MASTER_KEY` (value from `config/master.key`)
5. Enable PR environments: **Project Settings > Environments > Enable PR Environments**
6. Enable bot PR environments: **Project Settings > Environments > Enable Bot PR Environments**

> **Note:** If you use AI coding tools like Claude Code to create commits and pull requests,
> you must enable **Bot PR Environments**. Railway classifies PRs with commits from
> [supported bots](https://docs.railway.com/guides/environments) (including Claude Code)
> as bot PRs, and will not create preview environments for them unless this setting is turned on.

#### PR Preview Environments

When PR environments are enabled, Railway automatically:

- Creates an isolated environment (including a fresh PostgreSQL instance) for each pull request
- Provisions a unique URL (e.g., `*.up.railway.app`) for the PR environment
- Runs `db:prepare` on the empty database via the Dockerfile entrypoint
- Deletes the environment when the PR is merged or closed

### Fly.io

Deployment is configured via [`fly.toml`](fly.toml). PR preview environments are handled by GitHub Actions using [`superfly/fly-pr-review-apps`](https://github.com/superfly/fly-pr-review-apps).

#### Configuration

| Setting | Value | Description |
|---------|-------|-------------|
| Builder | Dockerfile | Uses the multi-stage Dockerfile generated by Rails |
| Region | nrt (Tokyo) | Primary deployment region |
| Release command | `bin/rails db:prepare` | Runs migrations before starting the app |
| Health check | `GET /up` | Rails built-in health endpoint |
| VM | shared-cpu-1x, 512 MB | Minimal resources for demo purposes |
| Auto-stop | Enabled | Machines stop when idle to reduce costs |

The Dockerfile's entrypoint also runs `db:prepare` before starting the server. The release command ensures migrations complete before any instances start.

#### Initial Setup

1. Install the Fly CLI: `curl -L https://fly.io/install.sh | sh`
2. Sign in: `fly auth login`
3. Create the app:
   ```bash
   fly apps create rails-preview-demo
   ```
4. Create a PostgreSQL cluster:
   ```bash
   fly postgres create --name rails-preview-demo-db --region nrt
   ```
5. Attach PostgreSQL to the app:
   ```bash
   fly postgres attach rails-preview-demo-db --app rails-preview-demo
   ```
6. Set secrets:
   ```bash
   fly secrets set RAILS_MASTER_KEY=<value from config/master.key> --app rails-preview-demo
   ```
7. Deploy:
   ```bash
   fly deploy
   ```

#### GitHub Actions Setup

Production deploys are handled by Fly.io's built-in GitHub integration (connect your repository in the Fly.io dashboard). PR preview environments require a GitHub Actions workflow:

- **[`fly-preview.yml`](.github/workflows/fly-preview.yml)** — Creates/updates/destroys preview apps for pull requests

Add the following secrets to your GitHub repository (**Settings > Secrets and variables > Actions**):

| Secret | Description |
|--------|-------------|
| `FLY_API_TOKEN` | Fly.io API token (get via `fly tokens create deploy -x 999999h`) |
| `RAILS_MASTER_KEY` | Value from `config/master.key` |

#### PR Preview Environments

Unlike Railway, Fly.io does not have built-in PR preview environments. Instead, the [`fly-preview.yml`](.github/workflows/fly-preview.yml) workflow uses the [`superfly/fly-pr-review-apps`](https://github.com/superfly/fly-pr-review-apps) GitHub Action to:

- Create an isolated Fly app for each pull request
- Attach a new database to the shared PostgreSQL cluster
- Set required secrets (`RAILS_MASTER_KEY`)
- Run `db:prepare` via the release command
- Destroy the app when the PR is merged or closed

The preview URL is posted as a comment on the pull request by the action.
