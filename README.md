# Rails Preview Demo

A minimal Rails application for verifying preview deployments on [Railway](https://railway.app) and [Fly.io](https://fly.io).

## Tech Stack

| Layer | Technology | Version |
|-------|-----------|---------|
| Language | Ruby | 3.4.8 |
| Framework | Rails | 8.1.2 |
| Database | PostgreSQL | 17 |
| Web Server | Puma | 7.2.0 |
| Assets | Propshaft + Importmap | 1.3.1 / 2.2.3 |

## Features

- **Post CRUD** — scaffold with title (string), body (text), and published (boolean)
- **Health Check** — `GET /up` returns 200 if the app boots successfully
- **Dockerfile** — multi-stage production build generated by Rails 8.1

## Routes

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Root (redirects to posts#index) |
| GET | `/up` | Health check |
| GET | `/posts` | List all posts |
| GET | `/posts/new` | New post form |
| GET | `/posts/:id` | Show a post |
| GET | `/posts/:id/edit` | Edit post form |
| POST | `/posts` | Create a post |
| PATCH/PUT | `/posts/:id` | Update a post |
| DELETE | `/posts/:id` | Delete a post |

## Local Development

### Prerequisites

- Ruby 3.4.8 (managed via [asdf](https://asdf-vm.com/))
- PostgreSQL 17
- Bundler

### Setup

```bash
bundle install
bin/rails db:create db:migrate
bin/rails server
```

Open http://localhost:3000

## Deployment

### Railway

Deployment is configured via [`railway.json`](railway.json).

#### Configuration

| Setting | Value | Description |
|---------|-------|-------------|
| Builder | Dockerfile | Uses the multi-stage Dockerfile generated by Rails |
| Health check | `GET /up` | Rails built-in health endpoint (timeout: 300s) |
| Restart policy | On failure (max 5 retries) | Prevents infinite crash loops |

The Dockerfile's entrypoint automatically runs `db:prepare` before starting the server. No custom start command is needed.

#### Dashboard Setup

1. Create a new project and connect this repository
2. Add a **PostgreSQL** service
3. On the app service, add a variable: `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
4. On the app service, add a variable: `RAILS_MASTER_KEY` (value from `config/master.key`)
5. Enable PR environments: **Project Settings > Environments > Enable PR Environments**
6. Enable bot PR environments: **Project Settings > Environments > Enable Bot PR Environments**

> **Note:** If you use AI coding tools like Claude Code to create commits and pull requests,
> you must enable **Bot PR Environments**. Railway classifies PRs with commits from
> [supported bots](https://docs.railway.com/guides/environments) (including Claude Code)
> as bot PRs, and will not create preview environments for them unless this setting is turned on.

#### PR Preview Environments

When PR environments are enabled, Railway automatically:

- Creates an isolated environment (including a fresh PostgreSQL instance) for each pull request
- Provisions a unique URL (e.g., `*.up.railway.app`) for the PR environment
- Runs `db:prepare` on the empty database via the start command
- Deletes the environment when the PR is merged or closed
